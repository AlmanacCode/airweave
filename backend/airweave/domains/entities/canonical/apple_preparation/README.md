# Offline Apple body preparation

`await prepare_notes_body(original, locked=..., limits=PreparationLimits(...))`
returns `PreparedNotesBody`: exact plain text, `plain_text_only` fidelity,
`rich_formatting`/`embedded_content` omissions, decoder/schema version, original
SHA-256 and process enforcement facts. Errors expose only stable codes.

This adapter does not read a provider/database, upload, change originals, or
publish projections. The caller must verify current record visibility and original
blob integrity before invocation and recheck visibility at projection publication.
Locked source content is rejected before creating a subprocess. Parsing a formerly
unlocked retained copy does not authorize displaying it after access withdrawal.

The caller supplies every limit. Input size is checked before process creation;
gzip expansion, decoded text and stdout/stderr are bounded. The single-use Python
process has CPU and wall limits and is killed/reaped on timeout, excess output,
failure and cancellation. On Linux, `RLIMIT_AS` limits address space before
parser import/decoding. macOS does not reliably enforce that limit: results
explicitly report `memory_limit_enforced=False`. Local tests run on macOS; Linux
kernel enforcement still needs deployment-platform qualification. CPU limits
count process CPU, while the parent wall deadline also bounds startup/wait time.

The child uses Python `-I`, a trusted absolute script path, and an environment
containing only PATH/LANG. Provider credentials are not forwarded. This **is not
an OS sandbox**: the child retains its user's filesystem/network privileges.

Only one complete gzip member and an initialized `NoteStoreProto` are accepted.
There is no plaintext/regex fallback. Google protobuf performs binary parsing.
Attribute runs, tables, mergeable embedded-object data, drawings and attachment
originals are not rendered here; these remain explicitly omitted. Native table
blobs are a different protobuf message and must not be submitted as note bodies.

## Messages typedstream preparation

`await prepare_message_body(original, limits=PreparationLimits(...))` returns
`PreparedMessageBody` through the same process runner. It accepts only an
NSAttributedString/NSMutableAttributedString root with an NSString backing value,
returns that exact text, and reports rich formatting/embedded content omissions.
Unknown classes remain inert Python archive representations. No Objective-C class
unarchiver or graph-wide string guessing is used. Malformed, truncated, trailing
and unsupported roots fail closed with `ApplePreparationError` stable codes.

The server dependency is unmodified `pytypedstream==0.1.0` from
https://github.com/dgelessus/python-typedstream. Tested upstream commit:
`773e000330eeae06abbc2d65d4bc4435f08f1bf1`. Runtime source headers specify
LGPL-3.0-or-later; installed wheel includes `COPYING.txt` (GPL3) and
`COPYING.LESSER.txt` (LGPL3). Keep the runtime Python source, copyright notices,
and both full licenses with distributed server artifacts; use a replaceable
installed dependency, not frozen/embedded code. No native desktop bundling is
part of this adapter. The dependency/lock and artifact inclusion belong to the
coordinator.

Upstream GPL3 section 0 distinguishes ordinary network interaction from conveying
copies. Distributing an image/on-prem copy requires reviewing LGPL3 section 4:
notices, both licenses, permitted library modification/reverse engineering for
those modifications, and a replacement-compatible shared library mechanism or
corresponding source/relink materials. These are concrete license conditions,
not a legal assurance of product compatibility. Full actual terms are in the
installed dependency's license files.

`tests/fixtures/GenerateMessages.swift` generates our own multilingual immutable,
mutable and unsupported-root fixtures with Foundation **NSArchiver encoding**.
Reproduce on macOS with `swift GenerateMessages.swift <fixtures-directory>`.
No private Messages content is used. Tests reject every truncated prefix of our
immutable fixture and exercise real worker decoding/budgets. Last upstream
release is from 2023; a representative current Messages archive corpus and Linux
kernel limit enforcement still need qualification. Rich text, attachments and
embedded object text are deliberately not claimed as rendered here.
